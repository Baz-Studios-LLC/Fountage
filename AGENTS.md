# Fountage project instructions

## Release versions

- The public release version is stored in `VERSION` and is currently **v001**.
- Keep **v001** throughout early development. Do not advance the version for builds, fixes, features, commits or milestones.
- Change the release version only when the user explicitly tells you to version the app.
- When authorized, use the sequence **v001, v002, v003**, with at least three digits.
- Show the same release label in Settings and About. Keep numeric platform metadata derived from `VERSION`.
- Document schema versions and external standards editions (such as APA 7) are separate from the app release label.

## Comic scripts

- The user approves an original Fountage comic-script house format; do not block on finding a universal publisher format.
- The default is **Fountage Standard**, designed to help new writers communicate clearly with artists and letterers.
- Base the house style on familiar full-script conventions used by comic creators. Do not invent a proprietary scripting language or unfamiliar terminology.
- Keep page/panel structure, artist descriptions, dialogue, captions and sound effects easy to distinguish. Document the conventions in `docs/COMIC_FORMAT.md`.
- Publisher-specific and user-created templates are additional options; a publisher compliance label requires a verified source.
